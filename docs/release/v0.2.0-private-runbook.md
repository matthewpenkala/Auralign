# Auralign 0.2.0 Private Operator Runbook

Auralign 0.2.0 is distributed only through the private repository release. The
bundles contain package code, installers, strict configurations, hash-pinned
dependency manifests, legal notices, and immutable model pointers. They never
contain model weights, Hugging Face caches, tokens, media, transcripts,
embeddings, profiles, datasets, containers, archived Git history, or validation
output.

The release lanes are Windows x64 CPU, Windows x64 CUDA 12.8 on the reviewed RTX
5090/Blackwell workstation, and macOS 14+ Apple Silicon CPU. Linux CUDA 12.6 is
retained only as secondary internal dependency evidence. MLX and MPS are
experimental and are not release acceptance lanes. Python 3.11 is mandatory.

## Install And Prepare A Native Host

Extract one native bundle into a new owner-controlled directory. On Windows,
run one explicit profile; do not reuse one environment for both lanes:

```powershell
.\install-windows.ps1 -Profile Cpu
.\bootstrap.ps1 -Config examples/config.strict-windows-amd64-cpu.yaml

.\install-windows.ps1 -Profile Cuda128 -Destination .auralign-runtime-cu128
.\bootstrap.ps1 -RuntimeDir .auralign-runtime-cu128 `
  -Config examples/config.strict-windows-amd64-cu128.yaml
```

CUDA additionally requires CUDA 12.8, cuDNN 9, the Visual C++ 2015-2022 x64
runtime, a real PyTorch CUDA operation, architecture coverage for the detected
RTX 5090, and CTranslate2 CUDA support. A CPU fallback is a failed CUDA lane.

On macOS:

```bash
./install-macos.sh
source .auralign-runtime/auralign-env.sh
./bootstrap.sh --config examples/config.strict-macos-arm64-cpu.yaml
```

The macOS installer validates the reviewed PyAV/TorchCodec FFmpeg ABI contract.
Do not claim readiness until strict `ltm doctor --startup` passes.

Community-1 is gated. Each operator must independently accept its upstream
terms and expose a read-scoped token only through `HF_TOKEN` or `LTM_HF_TOKEN`
during connected preparation. Never use a CLI argument or persisted token
store. Unset every supported token variable before offline validation.

## Create And Transfer The Owner-Local Capsule

On the authorized Mac, create the capsule once from the approved source and
validate it locally. Keep the output outside the repository:

```bash
uv run python scripts/validation_capsule.py build \
  --source /OWNER-LOCAL/APPROVED-SOURCE.mp4 \
  --destination /OWNER-LOCAL/auralign-validation-capsule-v1
uv run python scripts/validation_capsule.py verify \
  --capsule-dir /OWNER-LOCAL/auralign-validation-capsule-v1
```

Copy those exact bytes to Windows with owner-run SCP/SFTP over a trusted LAN or
VPN, or use an encrypted removable drive. GitHub must never transport the
capsule. Keep the separately acquired four-model cache outside the checkout as
well. Before sensitive bytes are transferred, pre-provision the Windows
destinations with an exact protected DACL. The evidence directory must be new
or empty; never reuse a non-empty directory for another candidate commit:

```powershell
$capsule = 'C:\AuralignValidation\capsule-v1'
$models = 'C:\AuralignModels\strict-v0.2.0'
$evidence = 'C:\AuralignValidation\acceptance-v0.2.0'
$runnerAccount = 'WORKSTATION\AuralignRunner'

if (Test-Path -LiteralPath $evidence) {
  if (@(Get-ChildItem -LiteralPath $evidence -Force).Count -ne 0) {
    throw 'The candidate evidence directory already contains files.'
  }
} else {
  New-Item -ItemType Directory -Path $evidence | Out-Null
}

function Set-AuralignPrivateDirectoryAcl {
  param([string]$LiteralPath, [string]$RunnerAccount)
  New-Item -ItemType Directory -Force -Path $LiteralPath | Out-Null
  $runnerSid = ([Security.Principal.NTAccount]::new($RunnerAccount)).Translate(
    [Security.Principal.SecurityIdentifier]
  )
  $expected = @(
    $runnerSid,
    [Security.Principal.SecurityIdentifier]::new('S-1-5-18'),
    [Security.Principal.SecurityIdentifier]::new('S-1-5-32-544')
  ) | Sort-Object -Property Value -Unique
  $acl = [Security.AccessControl.DirectorySecurity]::new()
  $acl.SetAccessRuleProtection($true, $false)
  foreach ($identity in $expected) {
    $rule = [Security.AccessControl.FileSystemAccessRule]::new(
      $identity,
      [Security.AccessControl.FileSystemRights]::FullControl,
      [Security.AccessControl.InheritanceFlags]'ContainerInherit, ObjectInherit',
      [Security.AccessControl.PropagationFlags]::None,
      [Security.AccessControl.AccessControlType]::Allow
    )
    [void]$acl.AddAccessRule($rule)
  }
  Set-Acl -LiteralPath $LiteralPath -AclObject $acl
  $observed = Get-Acl -LiteralPath $LiteralPath
  $observedSids = @($observed.Access | ForEach-Object {
    $_.IdentityReference.Translate([Security.Principal.SecurityIdentifier]).Value
  } | Sort-Object -Unique)
  $expectedSids = @($expected.Value | Sort-Object -Unique)
  $badRules = @($observed.Access | Where-Object {
    $_.IsInherited -or
    $_.AccessControlType -ne [Security.AccessControl.AccessControlType]::Allow -or
    $_.FileSystemRights -ne [Security.AccessControl.FileSystemRights]::FullControl -or
    $_.InheritanceFlags -ne [Security.AccessControl.InheritanceFlags]'ContainerInherit, ObjectInherit' -or
    $_.PropagationFlags -ne [Security.AccessControl.PropagationFlags]::None
  })
  if (-not $observed.AreAccessRulesProtected -or
      $observed.Access.Count -ne $expectedSids.Count -or
      @(Compare-Object $expectedSids $observedSids).Count -ne 0 -or
      $badRules.Count -ne 0) {
    throw "Private DACL verification failed for $LiteralPath"
  }
}

Set-AuralignPrivateDirectoryAcl $capsule $runnerAccount
Set-AuralignPrivateDirectoryAcl $models $runnerAccount
Set-AuralignPrivateDirectoryAcl $evidence $runnerAccount
```

Transfer the capsule and prepare the exact model cache only after that DACL
preflight. Then verify the capsule and configure the runner-local environment:

```powershell
python scripts\validation_capsule.py verify --capsule-dir $capsule
[Environment]::SetEnvironmentVariable(
  'LTM_VALIDATION_CAPSULE_DIR', $capsule, 'Machine'
)
[Environment]::SetEnvironmentVariable('LTM_MODEL_CACHE', $models, 'Machine')
[Environment]::SetEnvironmentVariable(
  'LTM_ACCEPTANCE_EVIDENCE_DIR', $evidence, 'Machine'
)
```

Replace `WORKSTATION\AuralignRunner` with the exact account that runs the
self-hosted runner service. Do not substitute the interactive setup account
unless it is also the service identity. During validation, Auralign verifies
and normalizes private DACLs to that current process account, Local System, and
local Administrators, so a separately owned directory cannot be mistaken for
runner-private storage.

Do not put the path, filenames, hashes, media, or generated evidence in GitHub
variables, secrets, workflow inputs, caches, or artifacts. Register the trusted
workstation with `self-hosted`, `Windows`, `X64`, and `auralign-gpu` labels.
The workflow writes only path-redacted native dependency SBOMs to the protected
runner-local evidence directory; it uploads nothing and still deletes runtimes,
media-derived outputs, transcripts, embeddings, and the temporary SBOM tool.
Use a new empty evidence directory for each exact candidate commit. Native SBOM
generation refuses to overwrite an existing file; preserve or quarantine prior
evidence outside the active directory instead of silently replacing it.

## Run Exact-Commit Native Acceptance

The owner dispatches `trusted Windows model validation` only on private `main`
and supplies the exact 40-character current `main` commit. The workflow runs CPU
and cu128 sequentially, emits only minimal pass/fail state, and deletes job
outputs. On macOS, run the same validator directly with networking blocked after
model preparation:

```bash
test "$(git branch --show-current)" = main
test -z "$(git status --porcelain=v1 --untracked-files=all)"
commit="$(git rev-parse --verify 'HEAD^{commit}')"
[[ "$commit" =~ ^[0-9a-f]{40}$ ]]
export LTM_VALIDATION_CAPSULE_DIR=/OWNER-LOCAL/auralign-validation-capsule-v1
unset HF_TOKEN LTM_HF_TOKEN HUGGING_FACE_HUB_TOKEN
LTM_OFFLINE=1 HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
PYANNOTE_METRICS_ENABLED=false \
.auralign-runtime/.venv/bin/python scripts/run_trusted_platform_validation.py \
  --profile cpu --config examples/config.strict-macos-arm64-cpu.yaml
```

Generate each native dependency SBOM from the exact installed environment that
passed. The generator strips local `file:` references and binds platform,
profile, commit, and Python version. Run the analogous command on the retained
Linux CUDA 12.6 host for `linux-amd64-cu126.cdx.json`; that secondary inventory
has no platform acceptance record but remains a release-assembly prerequisite.
Keep the same shell and candidate `commit` value established before validation;
fail if the checkout or worktree changes before evidence generation.

```bash
acceptance_dir=/OWNER-LOCAL/auralign-v0.2.0-acceptance
test "$commit" = "$(git rev-parse --verify 'HEAD^{commit}')"
test "$(git branch --show-current)" = main
test -z "$(git status --porcelain=v1 --untracked-files=all)"
if [ -e "$acceptance_dir" ]; then
  test -d "$acceptance_dir"
  test -z "$(find "$acceptance_dir" -mindepth 1 -maxdepth 1 -print -quit)"
else
  install -d -m 700 "$acceptance_dir"
fi
uv run --frozen python scripts/generate_environment_sbom.py \
  --python .auralign-runtime/.venv/bin/python \
  --platform darwin-arm64-cpu --profile cpu --commit "$commit" \
  --output "$acceptance_dir/darwin-arm64-cpu.cdx.json"
```

The Windows workflow intentionally uploads nothing. After both Windows lanes
pass, the owner retrieves the two SBOMs directly from the protected runner over
the same trusted SCP/SFTP channel (or encrypted removable drive) used for the
capsule. On the Windows host, create an owner-local checksum sidecar outside
GitHub, then transfer these three files to a temporary directory on the Mac:

```powershell
$sbomNames = @('windows-amd64-cpu.cdx.json', 'windows-amd64-cu128.cdx.json')
$checksum = Join-Path $evidence 'windows-sbom-SHA256SUMS'
$rows = foreach ($name in $sbomNames) {
  $item = Join-Path $evidence $name
  if (-not (Test-Path -LiteralPath $item -PathType Leaf)) {
    throw "Missing native SBOM: $name"
  }
  '{0}  {1}' -f (Get-FileHash -LiteralPath $item -Algorithm SHA256).Hash.ToLowerInvariant(), $name
}
[IO.File]::WriteAllLines($checksum, $rows, [Text.UTF8Encoding]::new($false))
```

Verify the transferred bytes before installing only the two SBOM files into the
owner-local acceptance directory. Keep the checksum sidecar in temporary local
evidence, not in the repository, acceptance directory, or release:

```bash
windows_transfer=/OWNER-LOCAL/temporary-windows-sbom-transfer
(cd "$windows_transfer" && shasum -a 256 -c windows-sbom-SHA256SUMS)
install -m 600 "$windows_transfer/windows-amd64-cpu.cdx.json" "$acceptance_dir/"
install -m 600 "$windows_transfer/windows-amd64-cu128.cdx.json" "$acceptance_dir/"
```

After personally observing each successful result, the owner creates a private
hash-bound acceptance record beside the corresponding native SBOM. This
explicit flag is a human attestation; an AI agent must never run it on the
owner's behalf:

```bash
acceptance_dir=/OWNER-LOCAL/auralign-v0.2.0-acceptance
uv run python scripts/write_platform_acceptance.py \
  --platform darwin-arm64-cpu --output-dir "$acceptance_dir" \
  --dependency-sbom "$acceptance_dir/darwin-arm64-cpu.cdx.json" \
  --owner-attests-pass
uv run python scripts/write_platform_acceptance.py \
  --platform windows-amd64-cpu --output-dir "$acceptance_dir" \
  --dependency-sbom "$acceptance_dir/windows-amd64-cpu.cdx.json" \
  --owner-attests-pass
uv run python scripts/write_platform_acceptance.py \
  --platform windows-amd64-cu128 --output-dir "$acceptance_dir" \
  --dependency-sbom "$acceptance_dir/windows-amd64-cu128.cdx.json" \
  --owner-attests-pass
```

The records conform to `docs/schemas/platform-acceptance-v2.schema.json` and
bind the commit, strict config, validator, model contract, Python version,
platform/profile, dependency-SBOM digest, and approved 12-character capsule-
manifest identifier. They contain no paths, full media hashes, transcript text,
embeddings, identities, or tokens. Record them only from a clean sanitized
`main` checkout.

## Assemble And Verify The Closed Release

Assembly requires a clean index and worktree, exact native acceptances, and a
complete four-model committed digest contract. It reruns lock/requirements
drift, tests, Ruff, mypy, REUSE, compliance, notices, vulnerability, reachable
history/large-blob, build, archive, SBOM, install-smoke, and checksum gates:

```bash
git status --short
uv run --frozen python scripts/assemble_private_release.py \
  --acceptance-dir "$acceptance_dir"
uv run --frozen python scripts/verify_private_release.py \
  --release-dir build/private-release-v0.2.0 \
  --commit "$(git rev-parse HEAD)"
```

The exact top-level allowlist is:

- `local_transcript_max-0.2.0-py3-none-any.whl`
- `local_transcript_max-0.2.0.tar.gz`
- `Auralign-0.2.0-windows-amd64.zip`
- `Auralign-0.2.0-darwin-arm64.tar.gz`
- `model-manifest.json`
- `Auralign-0.2.0-sboms.zip`
- `release-manifest.json`
- `SHA256SUMS`

Detailed native evidence and acceptance records stay owner-local and are not
release assets.

## Private Source Synchronization And Owner-Only Release Publication

An authenticated collaborator with current write permission may merge or fast-
forward reviewed source commits and perform a standard non-force push after an
explicit request and a successful dynamic private-push preflight. Only the owner
may tag, create the private release, and upload the eight allowlisted files.
Before tagging, confirm local/remote equality and private visibility.

```bash
git switch main
git pull --ff-only origin main
uv run python scripts/check_private_push_authorization.py
git push origin main
git fetch origin main
test "$(git rev-parse HEAD)" = "$(git rev-parse origin/main)"
gh repo view --json visibility --jq '.visibility == "PRIVATE"'
git tag -a v0.2.0 -m 'Auralign 0.2.0 private release'
git push origin v0.2.0
gh release create v0.2.0 build/private-release-v0.2.0/* \
  --repo matthewpenkala/Auralign --title 'Auralign 0.2.0' \
  --notes 'Private internal release; see bundled operator runbook.'
```

After publication, verify read-only that the release remains private, the tag
resolves to the accepted commit, and the remote asset names/sizes match
`release-manifest.json`. Download to a new owner-local directory and rerun
`verify_private_release.py`; do not upload the downloaded verification output.

Delete the Windows capsule after owner sign-off. No force-push, history rewrite,
public release, Authenticode, notarization, or standalone-app signing claim is
authorized for 0.2.0.
