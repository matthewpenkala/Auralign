# Auralign 0.2.0 Private Operator Runbook

Auralign 0.2.0 is distributed only through the private repository release. The
bundles contain source/package code, installers, strict configurations,
hash-pinned dependency manifests, legal notices, and immutable model pointers.
They never contain model weights, Hugging Face caches, tokens, media,
transcripts, embeddings, profiles, datasets, containers, or validation output.

Use Python 3.11. Windows support is x64 with either CPU or the reviewed CUDA
12.8 profile. macOS support is Apple Silicon on macOS 14 or later using the CPU
profile. MLX and MPS are experimental and are not part of release acceptance.

On Windows, run `install-windows.ps1 -Profile Cpu` or `-Profile Cuda128`, then
`bootstrap.ps1` with the matching strict configuration. CUDA requires a working
CUDA 12.8/cuDNN installation, Visual C++ 2015-2022 x64 runtime, a real PyTorch
CUDA tensor probe, GPU architecture coverage, and CTranslate2 CUDA support.

On macOS, run `install-macos.sh`, source the generated
`.auralign-runtime/auralign-env.sh`, then run `bootstrap.sh`. The locked PyAV
15.1.0 dependency provides the reviewed FFmpeg 7 ABI used by TorchCodec 0.7;
the installer validates that contract and creates only compatibility links
inside the installed dependency environment. Do not claim readiness until
`ltm doctor --startup` passes.

Community-1 is gated. Each operator must independently accept its terms and
provide a read-scoped token only through the environment during connected
preparation. Unset all token variables before offline startup validation.

The fixed private validation capsule is never transported through GitHub. Copy
the exact owner-hashed directory to the Windows workstation using owner-run
SCP/SFTP over a trusted LAN/VPN, or an encrypted removable drive. Restrict its
DACL, verify `SHA256SUMS`, and configure `LTM_VALIDATION_CAPSULE_DIR` only as a
runner-local system environment variable. Never place the path or media in
GitHub variables, secrets, inputs, caches, or artifacts.

Release assembly requires owner-local acceptance records for macOS CPU,
Windows CPU, and Windows CUDA 12.8 on the exact commit. The owner alone pushes
sanitized `main`, creates the annotated `v0.2.0` tag, creates the private
release, and uploads the closed artifact allowlist. No force-push, history
rewrite, public release, Authenticode, notarization, or standalone-app signing
claim is authorized for 0.2.0.
